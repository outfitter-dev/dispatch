# ADR-0022: Event Subscriptions

## Context

Agents often launch or coordinate work in other lanes and need to be told when that
work becomes actionable. Today they can poll `get`, `tail`, `history`, or `watch`, or
they can rely on a worker remembering to send a message back. That does not scale for
parallel worker lanes.

Dispatch already normalizes App Server notifications into `LaneEvent`s:

- `TurnStarted`, `TurnCompleted`, `TurnFailed`
- `LaneIdle` derived from `thread/status/changed`
- `ApprovalRequested` for command and file-change approval requests
- `ItemCompleted`, `DiffUpdated`, `StatusChanged`
- `TokenUsageUpdated`, `GoalUpdated`, `GoalCleared`, `ThreadCompacted`

It also has triggers for `turn_completed` and `waiting_on_approval`, but triggers are
action rules, not recipient-addressed subscriptions. ADR-0021 introduces a lane inbox
so event matches can create durable messages without necessarily starting a turn.

## Decision

Add event subscriptions as rules that create inbox messages from lane events or
semantic event buckets.

A subscription does **not** directly write to an agent thread. It matches a target
condition, creates an inbox message for a subscriber, and then applies delivery policy.
Starting a new agent turn is one delivery adapter, not the definition of a
subscription.

The primary CLI is:

```bash
dispatch subscribe <target-ref> [when:<condition>,to:<subscriber>,delivery:<mode>,tail:<n>]
dispatch subscriptions
dispatch unsubscribe <subscription-id>
```

The common case stays terse:

```bash
dispatch subscribe <target-ref>
```

Default expansion:

```text
when:done,to:self,delivery:turn,deliver:idle,tail:1,once:true,ack:auto_on_turn_start
```

`dispatch new` can create a subscription to the newly created lane:

```bash
dispatch new --name worker --text "Do the task" --subscribe
dispatch new --name worker --text "Do the task" --subscribe when:done,delivery:inbox
dispatch new --name worker --text "Do the task" --subscribe when:needs-attention,to:07uC61
```

`--subscribe` accepts a compact spec rather than adding many `--subscribe-*` flags.
Support `key:value` and `key=value` for operator convenience. Avoid shell-sensitive
syntax. Unknown keys fail loudly.

Initial spec keys:

- `when` — semantic condition bucket.
- `to` — subscriber lane ref/id, or `self`.
- `delivery` — `turn` or `inbox`.
- `deliver` — subscriber-side delivery policy, initially `idle` or `now`.
- `tail` — number of final messages to include; default `1`, `0` disables last
  message inclusion.
- `once` — default `true`.
- `ack` — `auto` or `manual`, mapped onto inbox acknowledgement policy.
- `attribution` — boolean; default `true`. Turn-delivered updates append the
  standard visible Dispatch attribution footer so a subscriber and operator can
  tell that the turn was generated by Dispatch. `attribution:false` preserves the
  compact legacy body.

Initial `when` buckets:

- `done` — target is no longer doing the current work, regardless of outcome.
  Includes completed, failed, stopped/interrupted when observable, or idle after an
  active turn. This is the default.
- `completed` — successful `TurnCompleted`.
- `failed` — `TurnFailed`.
- `needs-attention` — target is blocked or asking for outside input. Includes
  approvals, user-input requests, MCP elicitation, and dynamic-tool requests.
- `approval` — command, file-change, and permission approval requests only.
- `idle` — `LaneIdle`.
- `activity` — any normalized event, primarily for debugging and broad observation.

Default subscription messages include the target's latest message (`tail:1`). A
subscription can suppress this with `tail:0`. The latest message is derived from
persisted history after the condition match; if unavailable, the inbox message says so
explicitly.

Turn delivery appends the shared Dispatch attribution footer by default:

```text
Latest message:
...

dispatch (sub): [@worker](codex://threads/<thread-id>) `<ref>`
↳ completed | done
```

Delivery policies are subscriber-side:

- `deliver:idle` — create the inbox message immediately, but queue a turn only when
  the subscriber lane is idle.
- `deliver:now` — queue turn delivery immediately; existing lane queueing/backpressure
  still applies if the subscriber is busy.

This distinction is important:

- `when:idle` is about the target lane.
- `deliver:idle` is about the subscriber lane.

## Consequences

### Positive

- Agents can launch workers and be woken when work is actionable.
- Subscriptions can be inbox-only, so coordination updates do not always interrupt
  agents with new turns.
- `new --subscribe` makes delegated lanes easy without turning `new` into a maze of
  subscription flags.
- Semantic buckets (`done`, `needs-attention`) hide protocol churn while preserving
  precise matched-event data in JSON.
- The model composes with future delivery adapters: desktop notifications, webhooks,
  remote peers, or delayed delivery.

### Tradeoffs

- Requires a subscription store and matcher in the reactor/scheduler path.
- Requires careful idempotency so one event does not create duplicate inbox messages
  across daemon restarts or repeated status notifications.
- `done` is a semantic bucket, not a raw event. It must be documented and exposed with
  machine-readable `matched_event` / `outcome` fields.
- Inferring `self` depends on current Codex/Dispatch context. The command must fail
  clearly when no managed caller can be inferred.

## Alternatives considered

- **Make subscriptions directly call `send`** — rejected: it couples event matching to
  turn delivery and prevents inbox-only subscriptions.
- **Use `trigger add` for all subscriptions** — rejected: triggers are action rules
  and do not model subscriber inbox, acknowledgement, or delivery policy. Event
  subscriptions should be a higher-level operator primitive built on the same reactor
  facts.
- **Require `--event` raw names** — rejected: `--when` and semantic buckets are closer
  to operator intent and can include predicates such as `done` or `needs-attention`.
- **Add many `new --subscribe-*` flags** — rejected: `new` is already flag-heavy. A
  compact `--subscribe` spec is easier to extend and read.
- **Default to inbox-only delivery** — rejected for the common agent delegation case:
  if an agent asks to subscribe, it usually wants a queued turn when the worker is
  done. Inbox-only remains explicit with `delivery:inbox`.
